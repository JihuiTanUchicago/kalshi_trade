# Verified-memory research agent: stages and acceptance

Release: **0.1.0 candidate**, updated October 11, 2026, Asia/Shanghai. The implemented workflow is available locally through the CLI. Offline verification, actual Docker validation and a genuine Grok research/memory episode on an exploratory Alpaca import are complete. Qualified-data acceptance, measured-learning acceptance and real broker operation remain separate gates. The canonical status and handoff are in [PROGRESS.md](PROGRESS.md).

The first architecture improves a fixed foundation model through verified, persistent memory. It discovers hypotheses within a bounded research invocation, freezes a specification, implements a strategy, runs controls, challenges evidence, decides, and retrieves approved lessons for subsequent tasks. A separate worker executes eligible releases in an explicitly identified IBKR paper account. A rejected strategy is a valid research output.

## Stage 0: define the product and its authority

Freeze the first release around US common stocks and unleveraged, noninverse ETFs, daily observations, integer shares, next-open execution and USD accounts. Stock shorting is supported; ETF shorting is excluded. Scored dates begin in 2016 or later, with earlier observations permitted only for warmup. Previously inspected history remains exploratory.

The research model can propose hypotheses and implementations, inspect supplied excerpts, run the declared experiments, and request memory records. It cannot qualify data, edit graders, alter the protected mandate/cost policy, promote its own performance claims or access a broker. Host code validates every action before changing state. Foundation-model weights remain fixed.

Preservation tests require all hashes in `results/agent_v1/legacy_baseline.json` to match. The older six-ETF economic study and its rejection criteria are preserved. The new ledger has different declared accounting rules; passing legacy tests does not establish numerical equivalence between engines. Reusing that exact hypothesis requires a separately frozen compatibility study.

## Stage 1: implement the model boundary and spend controls

Adapters normalize `ModelRequest`/`ModelResponse` and usage without provider SDKs. Test chat-completions-compatible and native Anthropic message layouts, token-limit options, malformed responses, missing usage, transient failure, interrupted requests, configuration pins and schema repairs. Fixtures establish compatibility with the implemented contract; authentic requests establish compatibility with a configured service.

Acceptance requires one real `model-smoke` receipt for each configured adapter style, then the same controller functioning with either style. Use verified current token prices and locally configured credentials. Reserve spend before requests; if billing is uncertain, retain the reservation after restart. Validation allocations are $5 smoke, $35 learning comparison and $10 research, within $50 total in one persistent store. Do not change the benchmark or caps after seeing results.

## Stage 3: verify generated-code isolation on an actual runtime

Build the pinned image and record its local SHA-256 identity and dependencies. Run a valid generated strategy, then deliberately attempt network access, access to unmounted data/credentials/evidence, writes to protected paths, excessive memory/processes/output, hangs, malformed results and oversized/nonfinite state. Each attempt must be blocked or terminate within the declared limits, with no trusted performance output. An unavailable runtime must stop generated-code work.

Repeat a valid strategy and restart it from the same checkpoint; targets/state must match. Contexts arrive chronologically over standard input, with no full dataset mount. CPU/memory/process/output limits and a read-only unprivileged container are implementation controls, not proof against every possible container escape. Explicit JSON state is checkpointed; strategies needing a continuing random stream must serialize generator state.

This gate passed on October 10, 2026: 15 actual-container tests against the immutable Linux arm64 image in [image.lock.json](../sandbox/image.lock.json). Evidence: [container_tests.json](../results/docker_validation_2026-10-10/container_tests.json). The separate scripted synthetic episode passed six controlled trials, independent ledger verification, prefix and future-perturbation checks, decision and verified-memory stages through Docker. Its first mismatched-buffer test setup was rejected before execution and retained; the corrected specification was frozen in a new run. Run `sandbox/validation/run.py` and `sandbox/validation/research.py` using the README instructions to reproduce. Changing the image/runtime/platform requires revalidation.

## Stage 4: establish financial and statistical correctness

Check cash before and after settlement, short proceeds versus restricted collateral, recall covers, split-before-dividend ordering, dividend receivables versus cash, short dividend obligations, actual pay dates, delisting payouts, calendar-day borrow/financing, fees and liquidity/cash restrictions. Capital starts earning interest when the scored account starts. Unsupported fractional corporate actions block the affected run.

The independent verifier must reconstruct positions, cash, claims, fees, fills, NAV and returns from raw input and ledgers without importing the engine or planner. Deliberate changes to fills/cash must fail. Statistical controls use matching capital, data, timing and accounting. Report risky-benchmark exposures, drawdown, annual instability, uncertainty, and notional turnover separately from order counts. Broader factor/sector models and empirically calibrated capacity remain future extensions.

## Stage 5: complete a real research episode

Before results, freeze the hypothesis, dataset hash, benchmark, dates, timing, strategy, costs, rejection rules and limits. Register all six trials: baseline/candidate at normal, zero and doubled transaction/borrow costs. Complete ledger verification, restarted-prefix comparison and future price/dividend/volume/fee perturbations. New hypotheses or revisions get new specifications; failed attempts remain visible.

The model cannot change the protected mandate or default cost assumptions to produce a pass. Default risk allocation is $100,000, gross target <=100%, absolute target per asset <=25%, 5% cash buffer, 150% restricted short collateral and 0.1% prior-volume participation. Default costs are 5 basis points, $0.005/share and $1 minimum commission.

Automatic economic paper qualification additionally requires Sharpe gain >=0.10 over the frozen comparator, a positive one-sided 95% lower bound, block length >=21 sessions, >=2,000 bootstrap samples, at least two blocks of observations, drawdown deterioration <=2 percentage points, positive gain under doubled costs, independent verification and qualified data. A smaller exploratory bootstrap cannot qualify a release. Historical passage permits prospective paper investigation; it does not establish confirmed alpha.

Real acceptance requires a complete episode using a configured model, qualified data and a verified container, plus restart/resume evidence with no duplicated experiment or relaxed gate. A valid rejection satisfies research-workflow acceptance. Finding a profitable candidate is not a prerequisite for claiming the software ran correctly.

## Stage 6: prove that memory contains verified lessons

Persist observations copied from exact verified artifact pointers. Reject invented values, proxy-to-qualified upgrades, unsupported procedures and incompatible market/frequency/quality scopes. Preserve conflicting observations and explicitly scoped supersession. Demonstrate duplicate writes and restart retrieval without losing the underlying artifact.

V1 procedures are eight approved methodological templates. The agent chooses when evidence supports applying one; it does not invent and promote new executable procedures. Execution discrepancies enter operational memory, then can motivate a new investigation/specification. They do not silently rewrite an active strategy.

Post-episode consolidation must select three to six distinct approved procedures from supplied source handles and exact scalar-catalog paths. The host copies values and verifies the entire proposal before any finding is written; invented pointers, repeated procedures and unsupported evidence fail. Permit at most one schema repair, preserve failed attempts and resume a validated pending proposal without a new call. Task context must recheck memory identity/facts/qualification, exclude incompatible dataset scopes, rank relevance before enforcing its byte bound, and skip oversized records. October 11 genuine evidence: five new findings, 17 exact observations, unchanged proxy scope, no alpha assertion. Nine focused tests cover consolidation, zero partial writes, forged evidence, retrieval, frozen contracts and idempotent evaluation.

## Stage 7: measure improvement under fixed conditions

Freeze 40 distinct structured cases across timing, features, corporate actions, controlled comparisons, cost attribution, exposures, decisions and execution. Compare three conditions with two repetitions: **240 episodes total**. Pin the model/configuration, token limits, retrieved-context snapshots, ordering seed, case list and deterministic grader before calls. The grader's answers are withheld from model messages. No memory updates occur during the campaign; a consumed or partially used suite is retired.

Acceptance requires verified memory to improve success rate by >=10 percentage points over no learning and >=5 over raw logs, with a positive paired task-bootstrap 95% lower bound against no learning and zero hard errors. Timing, exposure, decision and execution failures count as hard errors. Complete every paired case/condition/repetition exactly once. A replay or mocked provider can never satisfy the learning gate.

Preflight the full worst-case cost against the $35 allocation. If it cannot fit, select an appropriate configured model before starting or leave acceptance pending. Do not reduce cases, repetitions or criteria after observing results. The result measures competence on these structured tasks; it does not establish broad research generalization or investment alpha. The real full-workflow episode is a separate stage-5 requirement.

The October 11 replacement design supplies the same explicit schemas/units/enums to all conditions and freezes task-relevant verified context alongside unranked raw chunks from the same underlying research artifacts. New scenario prompts must not match any reserved old suite. Pin evaluation/controller source hashes and system instructions before calls; unchanged strict grading remains authoritative. Semantic correctness is diagnostic only. The original evaluation/control stays preserved; a replacement result cannot retroactively qualify the original episode. A new result is evidence only within its frozen protocol, not an absolute-score comparison across protocol versions.

## Stages 8–9: validate paper execution and operational feedback

Complete the setup in the README: exact paper account, local Gateway, SDK/version compatibility, permissions, reviewed stable-ID/contract mappings, current shortable shares/fees, qualified current data and upcoming-session calendar. Start the worker explicitly. Validate initial flat-account activation and later strategy transitions, preserving risk history.

Before a batch, reconcile account/positions/orders/executions, check fresh borrow/fees and broker margin, and require conservative settled cash. Freeze every intent before the first send. Validate rejection, partial fill, cancellation, disconnect during acknowledgement and restart. Unknown acknowledgements pause; absence from the broker is not permission to resubmit. Recovery retains the original batch and rechecks aggregate cash/margin. If earlier sends are still pending, remaining sends wait for terminal reconciliation.

For **five consecutive actual US sessions**, require:

1. Reviewed current inputs and exact-account snapshots each session, with no stale or incomplete preflight.
2. Actual stock-long, stock-short and ETF-long round trips across the campaign; no ETF shorting. Use eligible economic releases when available.
3. No duplicated intent/fill, no unexplained position, no unresolved acknowledgement at acceptance, and all partial/terminal statuses preserved.
4. Post-close API capture and independently imported raw broker export for each session. The normalized statement must reproduce cash continuity, trade/commission activity, borrow/interest/tax entries, corporate actions and positions within the declared tolerance. Source authenticity and faithful normalization require operator review.
5. Attributed operational lessons retained with `strategy_alpha=false`; protective pause/resume and backup/restore rehearsals preserve all risk, memory, budget and intent state.

If no economic candidate passes, an **operator-only one-share engineering control** may exercise round trips in a dedicated paper account. It still requires qualified data, broker preflight and risk controls. Its release bypasses economic-performance qualification solely to test infrastructure; the research model cannot create this release. The explicit target sequence is stock `1 -> 0 -> -1 -> 0` and ETF `1 -> 0`, advanced by the operator over the session campaign. Such control trades are never alpha evidence and do not substitute for stage-7 learning results.

Do not infer production execution quality from IBKR paper fills. Five-session acceptance establishes the specified paper workflow, not live-capital readiness.
